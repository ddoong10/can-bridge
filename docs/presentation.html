can-bridge

한 AI 코딩 도구의 대화를
다른 도구로 그대로 이어가기
① 무엇인가② 핵심 아이디어③ 어떻게 발전시켰나 ④ 한계⑤ 오픈소스 연관성
문제

대화 맥락이 도구 안에
갇혀 있다

  • Claude Code에서 며칠 쌓은 작업 맥락을 Codex로 이어가고 싶다
  • 지금은 도구를 바꾸면 맥락을 처음부터 다시 설명해야 한다
핵심 아이디어

‘이어가기’는 사실
저장된 대화를 다시 읽는 것

  • 대화는 내 컴퓨터에 파일로 저장된다 — 그래서 다시 이어갈 수 있다
  • 그 파일을 다른 도구로 옮기면 대화도 따라 옮겨진다 → can-bridge
비유: 회의록을 넘기면 논의는 이어진다. 다만 그때의 ‘머릿속 생각’까지 복제되진 않는다.

구조

가운데 ‘공통 형식’을 거친다

두 도구의 저장 방식이 달라도, 공통 형식을 거쳐 서로 맞게 바꿔준다.
어려웠던 점

저장 형식이 공개되어
있지 않다

  • 두 도구의 대화 저장 방식은 공식 문서가 없다 → 실제 파일을 직접 뜯어보며 알아냄
  • 사소한 비공식 규칙 하나에도 막힘 (폴더 이름 규칙, 내부 인덱스 등)
  • 교훈: 에러 메시지가 아니라 ‘결과’로 확인했다
얼마나 잘 보존되나

다른 도구 vs 같은 도구

다른 도구로

  • 공통 형식을 거침
  • 호환되지만 약간 손실

같은 도구로

  • 원본을 그대로 보존
  • 거의 그대로 복원

저장 파일

  • 둘 다 담아둠
  • 나중에 다시 불러오기
“다른 도구로 갈 땐 공통 형식, 같은 도구로 돌아올 땐 원본 보존.”

개선한 것

옮길 때 생기는 손실을 줄임

  • 끊긴 도구 사용 기록을 짝 맞춰 메움
  • 대화의 순서를 원본 그대로 보존
  • 옮겨간 도구가 남의 도구를 자기 것으로 착각하지 않게 표시
  • 작업 폴더가 그새 바뀌면 경고해 줌
한계

정직하게 세 가지로 나눴다

A 해결

  • 코드로 고친 문제
  • 손실·착오 줄임

B 완화

  • 줄일 순 있지만
  • 0으로는 못 만듦

C 불가능

  • 원리적으로
  • 못 옮기는 것
“실패 목록”이 아니라 — 고칠 수 있는 것과 경계를 구분해 보여주는 것.
근본 한계 (C)

옮길 수 없는 것:
모델의 ‘속마음’

  • 저장 파일엔 대화 기록만 있다 — 모델의 내부 계산 상태는 들어있지 않다
  • 그래서 ‘생각의 흐름’이나 내부 캐시는 밖에서 꺼낼 수 없다
버그가 아니라 경계다. 우리는 기억 복제를 목표로 하지 않는다 — 보이는 기록만 정직하게 옮긴다.
오픈소스 연관성

작고 정직한
‘컨텍스트 변환 코어’

  • 대화가 로컬 파일로 남기에 외부 도구가 읽고 변환할 수 있다
  • 비슷한 프로젝트는 있지만 — 우리는 손실을 아는 것 + 원본 보존에 집중
  • 가볍고 의존성이 적어 다른 도구가 위에 얹기 쉽다
마무리
can-bridge는 기억을 복사하지 않는다.
대신 회의록을 가장 정직하게 옮긴다.
