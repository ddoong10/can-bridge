AI 코딩 도구 간 대화 맥락 이전 CLI (Claude Code ⇄ Codex)
"모델·도구를 바꿔도 대화를 이어간다"
문제핵심 아이디어구조 중간발표 이후 변화 3가지한계오픈소스 연계
문제

대화 맥락이 도구 안에 갇힌다

  • 며칠 쌓은 작업 맥락이 한 도구 안에 갇힘
  • 다른 도구로 옮기면 처음부터 다시 설명
  • 목표: 모델 복제가 아니라 작업 맥락의 이전
핵심 아이디어

/resume = 저장된 대화를 다시 읽는 것

  • 대화는 내 컴퓨터에 파일로 저장됨
  • /resume은 기억 복원이 아니라 그 기록을 다시 읽기
  • 그 파일을 다른 도구로 옮기면 → 대화도 옮겨진다
비유: 회의록을 넘기면 논의는 이어진다 — 그때의 머릿속 생각까지 복제되진 않지만.

긴 대화로 context가 터지는 문제 대응

  • 과거 대화를 통째로 넣으면 받는 쪽 context 과부하
  • 옵션으로 조절: 압축 이후만 · 큰 출력 잘라서 · slim 모드
  • 기본값은 최대 보존 — 줄이는 건 선택
변화 3 · 중간발표 이후

타겟이 오해하지 않게 (안전·정확도 장치)

  • 오해 방지: 남의 도구는 "과거 기록"으로 표시(자기 도구로 착각 X) · git 바뀌면 경고(옛 상태로 착각 X)
  • 정확도 수정: 끊긴 도구 호출 짝 맞춤 · 텍스트/호출 순서 보존
기반(양방향·도구 매핑·.cbctx 공유)은 중간발표에 이미 있었고, 이번엔 그 위에 "오해/사고 방지"를 얹음.
한계 ① · 천장

이건 우리만의 한계가 아니다

세션 파일에 있는 것 = 대화 기록뿐
모델 내부 상태(KV cache·attention·내부 reasoning)는 파일에 없음 — 모델·런타임 안에만
native /resume조차 복원 못 한다 — 저장된 대화를 다시 읽을 뿐. can-bridge는 이 천장을 그대로 따라감(같은 도구면 동등, 다른 도구면 근접). → "누구도 못 하는 것".

오픈소스 연계성

agent들이 주고받는 맥락의 포맷

여러 agent 실행·조율 (OpenClaw / Hermes 류 orchestrator)
↑ 그 사이에 넘길 컨텍스트
can-bridge — .cbctx 공통 컨텍스트 포맷 (하위 계층)
단기: agent memory를 꺼내고 넣는 import/export 포맷 · 장기: agent memory의 기본 저장 포맷 → "Hugging Face for contexts"(맥락을 저장·공유·검색). 차별점: 단순 요약이 아니라 도구 호출·결과·repo 상태·native 세션까지 손실을 알고 보존.
