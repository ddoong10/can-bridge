# can-bridge 발표 슬라이드 내용 (그대로 옮겨 적으면 됨)

> PPT 만드는 사람용. 각 슬라이드 = 제목 + 불릿. 평가(metric) 파트 제외.
> 인용 가능한 사실: 빌드 통과 · 자동 테스트 59개 통과 · 양방향 실제 검증.

---

### 슬라이드 1 — 표지
- **can-bridge**
- AI 코딩 도구 간 *대화 맥락 이전* CLI (Claude Code ⇄ Codex)
- "모델·도구를 바꿔도 대화를 이어간다"

### 슬라이드 2 — 문제
- 며칠 쌓은 작업 맥락이 **한 도구 안에 갇힘**
- 다른 도구로 옮기면 **처음부터 다시 설명**해야 함
- 목표: 모델 복제가 아니라 **작업 맥락의 이전**

### 슬라이드 3 — 핵심 아이디어
- 대화는 **내 컴퓨터에 파일로 저장**됨
- `/resume` = 기억 복원이 아니라 **저장된 기록 다시 읽기**
- 그 파일을 다른 도구로 옮기면 → **대화도 옮겨진다**

### 슬라이드 4 — 구조
- **꺼내기 → 공통 형식 → 넣기** (3단계)
- 한 도구 = 작은 변환기 하나 → 새 도구는 변환기만 추가
- **양방향** (Claude→Codex, Codex→Claude)

### 슬라이드 5 — [변화 1] 같은 도구로 돌아갈 땐 thinking까지 보존
- 예전: 같은 도구 왕복도 공통 형식을 거치며 **추론/thinking 손실**
- 지금: 같은 도구면 **원본 세션을 그대로 보존·복원**
- **Claude의 서명된 thinking까지 보존** → 실제 `claude --resume`로 검증(정상 재개)

### 슬라이드 6 — [변화 2] 긴 대화로 context가 터지는 문제 대응
- 거대한 과거 대화를 통째로 넣으면 받는 쪽 **context 과부하**
- 옵션으로 조절: **압축(compact) 이후만** / **큰 출력 잘라서** / **slim 모드**
- 기본값은 최대 보존 — 줄이는 건 **선택**

### 슬라이드 7 — [변화 3] 타겟이 오해하지 않게 (안전·정확도 장치)
- **오해 방지**: 남의 도구는 "과거 기록"으로 표시(자기 도구로 착각 X) ·
  작업 폴더(git)가 바뀌면 경고(옛 상태를 현재로 착각 X)
- **정확도 수정**: 끊긴 도구 호출을 짝 맞춰 메움 · 텍스트/호출 순서 보존
- *(기반은 중간발표에 이미 있었음: 양방향·도구호출 매핑·`.cbctx` 공유 —
  이번엔 그 위에 "오해/사고 방지"를 얹음)*

### 슬라이드 8 — 한계 ①: 이건 우리만의 한계가 아니다 (LLM resume의 천장)
- 모델 내부 상태(KV cache·attention·내부 reasoning)는 **세션 파일에 애초에 없음**
- 그래서 **native `/resume`조차 복원 못 함** — 저장된 대화를 다시 읽을 뿐
- can-bridge는 이 천장을 그대로 따라감 → *같은 도구면 native resume과 동등, 다른 도구면 근접*
- 즉 "우리가 못 하는 것"이 아니라 **원리적으로 누구도 못 하는 것**

### 슬라이드 9 — 한계 ②: 모델이 다를 때 *정확히* 무엇이 안 되나
> (포맷을 직접 뜯어보고 확인한 부분)
- **도구 이름·체계가 다름** — 기능이 겹치는 건 있음
  (예: Claude `Bash`↔Codex `shell_command`, `Edit`/`Write`↔`apply_patch`).
  하지만 인자·동작이 미묘하게 달라 **자동 변환은 위험** → 우리는 매핑 대신
  "과거 기록"으로 표시. `Task`(서브에이전트)·일부 MCP 도구는 **대응 자체가 없어**
  재현 불가
- **추론 표현이 벤더 전용** — Claude thinking은 서명이 붙어 Codex가 검증·사용 불가
  → 교차 시 폐기 (같은 벤더로 돌아올 때만 보존)
- **지시 체계가 다름** — Claude(system + `CLAUDE.md`) ↔ Codex(developer +
  `AGENTS.md`) → 우선순위 의미가 1:1 아님
- **추론 강도 노브가 다름** — Codex `reasoning_effort`(예: xhigh) 같은 설정은
  Claude에 대응 없음
- **행동이 다름** — 같은 텍스트라도 모델마다 도구 사용·판단 성향이 달라
  *이후 전개가 갈린다* (= "완전히 똑같이 이어진다"는 보장 없음)

- 한 줄: *"실패가 아니라 경계 — agent 복제가 아니라 작업 기록 이전이 목표"*

### 슬라이드 10 — 오픈소스 연계성
- 관련 오픈소스(OpenClaw/Hermes류)는 보통 **여러 agent를 실행·조율**하는 쪽
- can-bridge는 agent를 조율하는 프레임워크가 아니라 **context artifact를 표준화하는 하위 계층**
- 즉 경쟁 관계가 아니라 연결 가능: orchestrator가 agent 사이에 넘길 **공통 컨텍스트 패키지(.cbctx)** 로 사용 가능
- 많은 agent 오픈소스에는 자체 **memory/session store**가 있음 → 단기적으로 can-bridge는 그 메모리를 외부로 꺼내고 다른 도구에 넣는 **import/export 포맷**이 될 수 있음
- 최종 목표는 한 단계 더 나아가 **`.cbctx`가 agent memory의 기본 저장 포맷(main memory format)** 이 되는 것
- 장기적으로는 **Hugging Face for contexts**: `.cbctx` memory를 저장·공유·검색하고, 프로젝트를 만들 때 사용한 AI 협업 맥락까지 함께 보여주는 허브
- 차별점: 단순 Markdown 요약이 아니라 **도구 호출·결과·repo 상태·native 세션**까지 손실을 알고 보존
- 발표 멘트: *"OpenClaw나 Hermes가 여러 agent를 운영하는 엔진이라면, can-bridge는 그 agent들이 쓰는 메모리를 `.cbctx`라는 공통 포맷으로 저장하고 공유하게 만드는 하위 계층입니다. 모델에 Hugging Face가 있듯, 장기적으로는 작업 컨텍스트와 AI 협업 과정을 모으고 공유하는 허브가 될 수 있습니다."*

### 슬라이드 11 — 마무리
- can-bridge는 **기억을 복사하지 않는다**
- 대신 **회의록을 가장 정직하게 옮긴다**

## 부록 — 한계 한눈에 (발표·Q&A 백업)

> **한 줄**: can-bridge에서 안 되는 건 *대화를 옮기는 것*이 아니라,
> source agent의 **도구·추론·지시 체계·MCP 환경·UI 상태를 target의
> native 실행 상태로 바꾸는 것**.

**3단 정리 (제일 쉬운 버전)**
- ✅ **옮긴다**: 대화 내용, 작업 기록(명령·결과·결정)
- ❌ **못 한다**: 그걸 target의 *native 실행 상태*로 변환 (아래 표)
- 🚫 **누구도 못 한다**: 모델 내부 상태(KV cache 등) — 파일에 없음(슬라이드 8)

| 영역 | ✅ 옮기는 것 | ❌ 안 되는 것 | 완화 |
|---|---|---|---|
| **도구 호출** (Bash/Edit…) | 명령·인자·결과 기록 | native 도구로 1:1 재실행 변환 | 안전한 것만 best-effort 매핑 |
| **추론** (thinking/reasoning) | 같은 벤더면 원본 보존 | 교차 벤더 native 변환(서명) | same-tool 왕복만 |
| **지시 체계** (CLAUDE.md↔AGENTS.md) | 힌트·preamble로 전달 | instruction hierarchy 복제 | source 메타·경고 |
| **MCP/외부 도구** | 호출·입력·결과 기록 | 서버·인증·권한·실시간 상태 | "필요 도구 목록" manifest *(future)* |
| **active UI** (TodoWrite↔update_plan) | 계획 내용 기록 | target의 활성 plan UI로 복원 | 도구별 전용 처리 *(future)* |
| **분기 대화** (parentUuid DAG) | 최신 갈래(leaf chain) | 전체 가지 구조 | `.cbctx` branch graph *(future)* |
| **첨부·이미지** | 텍스트면 보존 | 이미지/바이너리/구조 복원 | `.cbctx` artifact 섹션 *(future)* |
| **벤더 전용 라인** (turn_context 등) | 같은 도구면 raw 보존 | cross-tool 보존 | *(의도된 설계 — 공통 이해 가능한 것만)* |

> 발표 멘트: *"안 되는 건 대화 이전이 아니라, Claude가 쓰던 도구·추론·지시 체계를
> Codex의 native 실행 상태로 바꾸는 것입니다. 우리는 이를 억지로 재실행 가능한
> 척 위조하지 않고, foreign tool history와 `.cbctx`로 정직하게 보존해 넘깁니다."*
